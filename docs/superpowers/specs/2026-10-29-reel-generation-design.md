# Реальная генерация Raw2Reel

Статус: предложение для согласования перед реализацией.

## Назначение

Превратить текущую демонстрацию в приложение, которое принимает исходное
видео и выдаёт настоящий вертикальный MP4. Пользователь выбирает материал,
при необходимости человека в кадре и музыку, запускает обработку, смотрит
результат и скачивает файл.

Пользователь подтвердил доступ к Muse и задал имя переменной ключа:
`MODEL_API_KEY`. Наличие и работоспособность самого ключа ещё не проверены.
Всё остальное ниже — предлагаемые технические решения.

## Подходы

1. **Muse для анализа и транскрипции, FFmpeg для монтажа — рекомендуется.**
   Сохраняет продуктовую идею, использует существующие FastAPI и Bun,
   не требует GPU. Качество плана монтажа нужно проверять на реальном видео.
2. **Сначала FFmpeg с фиксированной нарезкой, затем AI.** Быстрее даёт файл,
   но откладывает поиск интересных моментов и субтитры. После подтверждения
   доступа к Muse этот промежуточный режим не нужен как отдельный продукт.
3. **Полностью внешний сервис монтажа.** Потребует нового поставщика и
   контракта: найденные Muse API возвращают текст и геометрию, готового
   смонтированного MP4 они не обещают.

## Объём первой версии

- Один исходный MP4 или MOV до 150 MiB и 120 секунд; проверяется фактический
  контейнер, длительность, наличие видеопотока и возможность декодирования.
- Один результат до 30 секунд, не длиннее исходника, 720×1280, 30 fps,
  H.264/AAC, с обычным воспроизведением в браузере и скачиванием MP4.
- Muse Spark предлагает хук и интервалы нарезки на основании видео.
- Muse Voice распознаёт речь; субтитры отображаются по репликам.
- Пользователь может загрузить собственный музыкальный файл или сохранить
  исходный звук без музыки. При музыке монтаж привязывается к определённым
  по аудиофайлу долям; существующие названия треков без файлов убираются.
- Для выбора человека используется SAM 3.1: реальные миниатюры людей и
  сопровождение выбранного объекта. Интерфейс говорит о людях/объектах,
  не обещает биометрическое узнавание лица между разными сценами.
- Выбор человека влияет и на нарезку, и на кадрирование: фрагменты без
  выбранных объектов исключаются, как обещает текущий экран генерации.
  Для нескольких выбранных людей достаточно присутствия хотя бы одного
  (предлагаемое правило). Если подходящих интервалов нет, генерация
  завершается понятной ошибкой и предложением изменить выбор.
- При отсутствии выбора человека применяется центральное кадрирование.
  При потере объекта соответствующие интервалы исключаются; если из остальных
  удалось собрать ролик, это ограничение отмечается в результате. Неудачный
  вызов SAM не выдаётся за успешное сопровождение.
- Состояние загрузки, очередь, этапы обработки, ошибки и повторный запуск
  показываются по фактическим ответам сервера.

Не входят в эту версию: монтаж нескольких исходников, публикация в соцсети,
синтез голоса, пословная подсветка, аккаунты с паролями, совместное редактирование.
Это ограничения предлагаемой первой версии, а не уже принятые пользователем.

## Устройство

**React:** существующая студия и FSD сохраняются. Настоящий API-клиент заменяет
таймеры и моки. Проигрыватель использует `<video>`, кнопка скачивания — файл
результата. Музыка и выбранные объекты необязательны. Ошибки не оставляют
интерфейс в состоянии бесконечной генерации.

**Bun:** публичный API, гостевая сессия, загрузка/выдача медиа, проверка
принадлежности проектов, состояние задач. Сессия хранится в HttpOnly cookie
с SameSite=Lax и Secure в production; идентификаторы файлов сами по себе
не дают доступ к чужим проектам. Mongo хранит сессии, проекты, медиа и задачи.
Файлы находятся в Azure Blob Storage, а не внутри документов Mongo.

**FastAPI:** существующие служебные маршруты плюс один фоновый обработчик.
Он забирает задачи из Mongo, получает файлы из Blob, вызывает Meta и запускает
FFmpeg. Новые публичные маршруты AI не требуются. Секрет Meta доступен
только AI-сервису; в браузер и ответы API он не попадает.
Для этого при настройке compose ключ нужно вынести из общего `app.env`
в отдельный файл окружения AI: сейчас общий файл подключается и к backend.

**Очередь:** Mongo, без Redis и нового сервиса. Атомарное получение задачи,
lease с heartbeat и ограниченное восстановление после перезапуска. Один
одновременный обработчик на хосте с 2 vCPU/4 GB. Повтор запроса генерации
с тем же идентификатором не создаёт дубликат задачи.

## Контракт приложения

- `POST /api/projects`: создать проект в текущей гостевой сессии.
- `POST /api/projects/:id/assets`: зарегистрировать видео или музыку.
- `PUT /api/projects/:id/assets/:assetId/content`: загрузить тело файла потоком,
  с ограничением фактического числа байт; не собирать видео целиком в RAM.
- `POST /api/projects/:id/analysis`: поставить анализ загруженного видео в очередь.
- `GET /api/projects/:id`: вернуть состояние проекта, метаданные, найденные
  объекты, миниатюры, текущую задачу и результат. Frontend опрашивает его.
- `POST /api/projects/:id/renders`: зафиксировать настройки и поставить
  генерацию; тело содержит выбранные ID объектов и необязательный ID музыки.
- `GET /api/projects/:id/assets/:assetId/content`: выдать доступное сессии
  медиа, включая поддержку Range для проигрывателя.

Все операции проверяют сессию и владельца. Ошибки возвращают стабильный код
и понятное сообщение; ответы внешнего API и секреты не пересылаются клиенту.
Служебные `/health`, `/ready`, `/version` сохраняют текущую семантику.

## Обработка

1. Проверить файл через ffprobe. Зарегистрировать и поставить анализ в очередь
   только после завершённой загрузки. Незавершённая загрузка не генерируется.
2. Muse Spark получает видео через Files API и составляет проверяемый план
   монтажа. JSON проверяется схемой; интервалы должны находиться в исходнике,
   иметь положительную длительность и укладываться в предел результата.
3. Для выбора людей SAM анализирует материал; идентификаторы сопровождения
   сохраняются с источником и временными границами, а не объединяются
   произвольно между сценами. Недоступность SAM отображается явно, генерация
   без выбора объекта остаётся доступной.
4. При генерации извлечь WAV: mono, PCM16, 24 kHz. Если звука или речи нет,
   не добавлять выдуманные субтитры. Voice вызывается в режиме с репликами.
5. Для загруженной музыки определить ритм по реальному аудио. Если уверенного
   ритма нет, выполнить обычную нарезку и сообщить, что синхронизация не применена.
6. FFmpeg нарезает проверенные интервалы, кадрирует, переносит таймкоды
   субтитров на итоговую шкалу и сводит исходную речь с музыкой. Для дорожки
   короче результата допускается ограниченное повторение. Выход всегда
   ограничен итоговой длительностью.
   При выборе нескольких людей кадр учитывает рамки присутствующих выбранных
   объектов. Если их нельзя вместить обрезкой 9:16, используется вписывание
   изображения с полями, чтобы не обрезать выбранных людей.
7. Проверить результат через ffprobe, сохранить MP4 в Blob и только затем
   перевести задачу в `done`. Исходные настройки и итоговые длительность,
   количество склеек и применённые функции сохраняются для интерфейса.

## Надёжность и ограничения ресурсов

- FFmpeg получает аргументы массивом, без shell; URL и пути модели не исполняются.
- Обработка ведётся во временном каталоге на диске. Входы и выходы не
  превращаются в большие base64-строки в памяти приложения.
- FFmpeg ограничивается одним потоком; на задачу задаётся предел 10 минут.
  Достижимость этого времени и лимита AI-контейнера 640 MB проверяется
  отдельно; успешные unit-тесты не считаются проверкой ресурсов production.
- У API Meta есть таймауты и ограниченные повторы для 429/временных сбоев;
  401/403 сообщаются как ошибка настройки, а не повторяются бесконечно.
- Временные файлы удаляются после задачи; незавершённые загрузки и медиа
  проектов имеют срок хранения 24 часа. Суммарный лимит медиа гостевой
  сессии — 1 GiB. Очистка обрабатывает только записи с истёкшим сроком.
- Деплой устанавливает FFmpeg с нужными кодеками, шрифтами и фильтром
  субтитров; ключ задаётся секретом окружения, не параметром сборки образа.

## Проверка результата

- Тесты владения проектом, ограничений потоковой загрузки, постановки и
  восстановления задач, проверки JSON-плана и переноса таймкодов субтитров.
- Проверка HTTP-контрактов Meta с подставным HTTP-транспортом и реальными
  документированными схемами; это не доказательство доступности аккаунта.
- Интеграционный тест с небольшим сгенерированным исходником и настоящим
  FFmpeg: размеры, кодеки, длительность, наличие ожидаемых потоков.
- Проверки frontend: типы, линтеры, FSD, форматирование и production-сборка.
- Отдельный ручной сквозной прогон с `MODEL_API_KEY` и тестовым видео:
  загрузка, анализ, необязательный выбор объекта и музыки, генерация,
  воспроизведение, скачивание. Проверить в том числе ролик без речи.
- Для сквозной проверки также нужны настроенные Mongo и Blob. Локальный
  вариант — MongoDB и Azurite с отдельным compose, без подключения к боевым данным.

## Порядок работ после согласования

1. API, гостевая сессия, потоковая загрузка, Mongo/Blob, локальное окружение.
2. Очередь и клиенты Meta; анализ, объекты и транскрипция.
3. Монтаж, музыка, субтитры и проверка настоящего MP4.
4. Подключение студии, ошибки, проигрывание и скачивание.
5. Контейнеры, автоматические проверки и сквозной прогон при доступных секретах.

Детали модулей, названия коллекций и конкретный алгоритм определения ритма
оставлены исполнителю. Источники API перечислены в
[справке интеграции](../../integrations/meta-model-api.md).
