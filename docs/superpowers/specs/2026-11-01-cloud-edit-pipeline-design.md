# Облачный пайплайн эдитов с выбором персонажей

Статус: согласовано пользователем, реализован AI-этап. CLI и HTTP v2 доступны;
подключение нового потока к frontend/backend остаётся отдельной доработкой.

## Цель и ограничения

Из одного исходного видео получить каталог персонажей с реальными миниатюрами,
дать пользователю выбрать одного или нескольких, затем собрать эдит до 30 секунд
под выбранную музыку. Сократить объём видео, отправляемого Spark для подробного
анализа. Все модели работают через облачный Meta Model API и MODEL_API_KEY:
SAM 3.1, Muse Voice Transcribe и Muse Spark. FFmpeg локально выполняет только
декодирование, извлечение кадров, определение монтажных склеек, анализ битов,
кроп, монтаж и сведение звука. Локальных нейросетей и весов нет.

Сначала реализуется AI-пайплайн и его HTTP/CLI-контракт. Существующий внешний
вид приложения не меняется. Изменения существующего frontend/backend в этот
этап не входят: для них описывается контракт подключения к уже имеющимся
NATS, worker, MediaRepository и render jobs. Прежний /v1/render остаётся
совместимым; новый поток вводится отдельно как v2.

## Выбранный подход и альтернативы

Выбраны исключительно облачные модели. Альтернатива с локальными YuNet/SFace
отклонена пользователем. Каталог строится через облачную локализацию лиц SAM
и сопоставление анонимных персонажей Spark на компактных наборах изображений.
Это гипотеза реализации, а не подтверждённая точность: SAM с запросом face и
Spark для сопоставления нужно проверить на реальном фильмовом исходнике.
Если такой SAM-промпт не даёт пригодных боксов, Spark image grounding служит
облачным fallback локализации, с явным учётом дополнительных запросов.

API SAM документирует concept, box и point prompts. Отдельное фото лица не
считается документированным способом задать личность для трекинга. Поэтому
референс всегда связан с исходным кадром, его номером и box. SAM ID стабилен
в пределах запроса/трека; идентичность между сценами устанавливает отдельный
этап, а не предположение о неизменном SAM ID.

## Подготовка до выбора пользователя

1. Проверить исходник и вычислить SHA-256. Создать manifest кадров/сцен,
   учитывая поворот, фактические timestamps и VFR; не вычислять время простым
   делением на предполагаемый FPS. Провести ограниченное по бюджету сканирование
   по всей длительности, плотнее около коротких сцен.
2. На представительных кадрах SAM локализует лица; FFmpeg вырезает превью.
   Это обнаружение кандидатов, не обещание найти абсолютно все лица.
3. Spark сравнивает небольшие пакеты кандидатов и сохранённые референсы,
   объединяет появления анонимных персонажей. Никаких имён реальных людей,
   поиска внешних персон или чувствительных характеристик. Неуверенное
   совпадение сохраняется отдельно, а не склеивается принудительно.
4. Вернуть для каждого person_id лучшие JPEG-миниатюры, reference frame/time,
   bbox, список наблюдений и информацию об охвате сканирования.
5. Транскрибировать исходный звук Voice и сохранить реплики с таймкодами.
   Транскрипция нужна для отбора даже при выключенных видимых субтитрах;
   для немого видео она пуста. Её задача может выполняться после каталога,
   но должна быть готова до смыслового отбора.

## После выбора

Клиент возвращает analysis_id и выбранные person_id. По умолчанию сохраняем
сцены, где присутствует хотя бы один выбранный персонаж (OR). Сервер загружает
референсы сам: присланные картинки не подменяют сохранённый анализ.

1. Использовать наблюдения выбранных персонажей как seed boxes по сценам.
   Проверить недостаточно просмотренные сцены и отметить неопределённые.
   Запустить SAM по ограниченным клипам с повторной инициализацией на склейках.
   Для кропа трекать область персонажа, а не только тесную рамку лица;
   точка лица может служить seed, корректность области проверяется.
2. Сохранить координаты и состояния present/absent/unknown. Нельзя считать
   отсутствие результата на непроверенном интервале доказанным absent.
   Хранить отображение координат и времени клипа обратно в исходник.
3. Измерить биты выбранной музыки до финального сценария. Достоверность
   оценки ритма хранить, при низкой уверенности не обещать точную beat sync.
4. Первый проход Spark получает компактные интервалы присутствия, сцены и
   транскрипцию. Ранжирует кандидатов в пределах video-review budget. Сохраняет
   контекст перед/после реплики; отсутствие диалога не снижает автоматически
   ценность действия. При unknown не исключать сцену молча.
5. Второй проход Spark смотрит только видео кандидатов и формирует сценарий
   и структурированный EditPlan. Если кандидатов мало, расширить просмотр
   в пределах установленного бюджета; при исчерпании вернуть явный результат
   недостаточности материала, а не заявить полноту анализа.

## EditPlan и детерминированный рендер

EditPlan содержит narrative, ordered clips, source_start/source_end,
output_start/output_end, выбранные person_id, audio_phase и music_start_offset.
Переход impact_start задан в шкале готового ролика и согласован с битами
и выбранным началом музыки. Для плана отдельно хранятся текстовый сценарий,
причины отбора и ссылки на проверенные видео-кандидаты.

Валидатор проверяет диапазоны, конечные числа, отсутствие неподдерживаемого
пересечения исходных интервалов, непрерывность выходной шкалы и итоговую
длительность. После округления к кадрам повторно вычисляются выходные
таймкоды, субтитры, биты и аудиопереход. Модель не задаёт команды FFmpeg.

В первой части исходная речь приоритетна, музыка приглушена с ducking.
Во второй части музыка усиливается, исходный звук понижается. Переход плавный,
громкости нормализованы, пики ограничены. Конкретные уровни выбираются
реализацией и проверяются на исходниках, а не считаются универсальными.

Кроп 9:16 следует сглаженному центру tracked region в пределах кадра,
сбрасывая сглаживание на склейках. При нескольких целях стремится вместить
их общий bbox; если это невозможно, основной персонаж — первый выбранный.
При потере трека кратко удерживает последнюю позицию, затем использует
центральный кроп и записывает предупреждение. Не обещаем, что разнесённые
персонажи одновременно поместятся в 9:16.

## Артефакты и API

AI получает байты файлов, не произвольные внешние URL или серверные пути.
Для новой версии предварительный анализ и генерация — отдельные операции:

- prepare(video) -> каталог JSON + JPEG + transcript + internal observations;
- render(video, analysis JSON, selected person_ids, music, options) -> MP4.

Обе операции синхронные внутри AI; длительные задачи и пользовательский статус
принадлежат существующей очереди/воркеру бэкенда. Первый этап позволяет
проверить обе операции в CLI/Swagger, без выдуманного AI-хранилища пользователей.
Prepare возвращает JSON с catalog, thumbnails и calls. Миниатюры передаются
как JPEG data URLs по observation ID. Backend сохраняет полный ответ, связывает
его с владельцем и исходным media ID; frontend получает карточки персонажей.
Render принимает тот же JSON в текстовом multipart-поле analysis вместе с видео
и музыкой. Никаких путей хранилища или внутренних analysis_id в AI-контракте нет.
Лимит JSON 16 MiB, миниатюры до 256×256 и 64 KiB; данные и fingerprint валидируются.
CLI сохраняет/читает тот же ответ через prepared.json; backend отвечает за постоянное хранение.

Артефакты отдельно: observations, face catalog, transcript, tracks,
candidates, edit plan и render manifest. Ключ переиспользования включает
fingerprint исходника, версию модели, prompt/schema version и параметры.
Треки дополнительно зависят от выбранных person_id. На первой стадии
переиспользование обеспечивают сохранённые артефакты; межзапросный глобальный
кеш/новая база данных не вводятся. analysis_id не заменяет проверку владельца
медиа на бэкенде.

## Порядок реализации и проверки

1. Реальный ограниченный API-прогон: проверить SAM face localization,
   сопоставление Spark и SAM track на коротком клипе. Измерить вызовы и охват.
   При неработающей гипотезе сообщить результат, не скрывать её за mock.
2. Схемы артефактов, Meta adapters, подготовка каталога и CLI/HTTP v2.
3. Трекинг с привязкой ко времени, отбор кандидатов, EditPlan и переиспользование.
4. Динамический кроп, двухфазное аудио, рендер и документация интеграции.

Проверки: парсинг SAM stream и ошибок, смена сцен и SAM IDs, исходные/клиповые
таймкоды и VFR, неизвестное присутствие, чужой fingerprint, неверный JSON и миниатюры,
бюджет просмотра, повторное использование транскрипции, длительность/порядок,
мультиперсонажный кроп и аудиопереход. Платный smoke выполняется ограниченно
на коротком фрагменте существующего тестового видео; полный фильм автоматически
не отправляется многократно. Наблюдаемость: модели, стадии, media seconds,
число вызовов, usage где доступен, warnings; ключи и raw private errors не логируются.
