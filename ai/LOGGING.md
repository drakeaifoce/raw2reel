# Логи AI-сервиса

Сервис и CLI пишут структурированные события в stderr. Результат CLI остаётся в stdout.
Настройки в окружении AI-сервиса или файле, переданном CLI через `--env-file`:

```dotenv
LOG_LEVEL=INFO
LOG_FORMAT=json
```

Для чтения локально можно поставить `LOG_FORMAT=console`. `LOG_LEVEL=DEBUG`
добавляет запуск/завершение команд FFmpeg и успешные health-запросы.
При INFO health-проверки не засоряют логи; их ошибки видны.

Каждый HTTP-запрос получает `request_id`, возвращаемый заголовком `X-Request-ID`.
Бэкенд может передать этот заголовок сам (1–128 ASCII-букв, цифр, `.`, `_`, `-`,
первый символ — буква или цифра). Иначе сервис создаёт ID.
Он проходит в поток выполнения пайплайна и объединяет события одного запроса.
CLI создаёт ID на каждый запуск. Версия сборки находится в поле `version`.

События:

- `request_started` / `request_completed`: ручка, HTTP-статус и время.
- `upload_saved`: тип файла и количество байтов без имени и содержимого.
- `pipeline_started` / `pipeline_completed` / `pipeline_failed`: операция, итоговые счётчики и время.
- `stage_started` / `stage_completed` / `stage_progress`: этап, время, прогресс группировки.
- `faces_filtered`: число обнаруженных и оставшихся лиц, причины удаления.
- `model_call_started` / `model_call_completed` / `model_call_failed`: модель, этап, время и доступные счётчики использования.
- `meta_request_retry`: номер попытки, причина, HTTP-статус или тип сетевой ошибки и задержка.
- `transcription_started` / `transcription_completed`: модель, время, число реплик.
- `media_command_failed`: инструмент, причина, код завершения и время.
- `request_failed` / `command_failed`: тип ошибки, безопасный код и место сбоя.

Повторы в логах Meta относятся к вызовам моделей внутри одного HTTP-запроса.
Попытки задач очереди отслеживает бэкенд; AI-сервис не знает их номера.

Ключи, заголовки авторизации, query-параметры, промпты, транскрипция,
медиа, полные пути и аргументы FFmpeg не записываются. Стек исключения содержит
только имя файла, строку и функцию без текста исключения, исходных строк и локальных переменных.
CLI `--debug` добавляет такой стек и для ожидаемых ошибок ввода.
Необработанная ошибка HTTP возвращает безопасный ответ 500 с `request_id`.

Локальный просмотр:

```bash
cd ai
.venv/bin/uvicorn raw2reel_ai.main:app --host 0.0.0.0 --port 8000
```

В Docker: `docker logs -f <имя-контейнера-ai>`.
