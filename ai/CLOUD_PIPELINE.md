# Облачный пайплайн с выбором лиц (v2)

Все модели работают через Meta API и MODEL_API_KEY: SAM 3.1, Muse Spark,
Muse Voice Transcribe. Локально работают FFmpeg и Pillow. Старый /v1/render
сохранён; текущий backend worker использует v1 до отдельного подключения v2.

## Контракт для бэкенда

### POST /v2/prepare

Авторизация: `Authorization: Bearer <AI_SERVICE_TOKEN>`.
Тело: multipart/form-data, обязательный файл `video`.
Ответ: application/json, подготовленный анализ:

```json
{
  "catalog": {
    "version": 2,
    "source_sha256": "…",
    "source_duration": 208.4,
    "scenes": [{"start": 0, "end": 4.2}],
    "observations": [{"id": "o0", "scene": 0, "time": 2.1,
                      "bbox": [0.2, 0.1, 0.4, 0.5]}],
    "people": [{"id": "p1", "label": "Character 1", "observation_ids": ["o0"]}],
    "turns": [{"startMs": 100, "endMs": 900, "transcript": "Hello"}],
    "warnings": [],
    "provenance": {"schema": "2", "sam": "sam-3.1"}
  },
  "thumbnails": {"o0": "data:image/jpeg;base64,…"},
  "calls": []
}
```

Это сокращённый пример структуры; настоящий ответ содержит всю карту сцен.
Бэкенд сохраняет полный ответ и связывает его с владельцем и исходным media ID.
Для отображения карточки p1 можно взять первую observation из observation_ids
и соответствующую картинку `thumbnails.o0`. Это готовый data URL для img.src.
Бэкенд может отдельно публиковать миниатюры через своё хранилище, сохраняя
исходный JSON анализа для следующего серверного вызова.

### POST /v2/render

Авторизация та же. Тело multipart/form-data:

| Поле | Содержимое |
|---|---|
| video | Файл того же исходного видео |
| analysis | JSON-строка с полным ответом /v2/prepare (`JSON.stringify(savedAnalysis)`) |
| person_ids | JSON-массив выбранных ID, например `["p1"]` |
| music | Необязательный аудиофайл |
| duration | Длительность результата в (0,30], по умолчанию 27 |
| captions | true / false, по умолчанию true |

`analysis` — текстовое поле, не файл. Не нужно передавать внутренний analysis_id
FastAPI: бэкенд сам находит сохранённый результат по своему ID и сериализует его.
Возвращать только catalog недостаточно: thumbnails тоже нужны как референсы Spark.
AI проверяет SHA-256 видео, структуру анализа, выбранные ID и миниатюры.
Максимальный размер analysis JSON — 16 MiB; миниатюры JPEG до 256×256 и 64 KiB.

Ответ 200: готовый video/mp4. Бэкенд сохраняет его через MediaRepository и
завершает свою задачу. AI не хранит постоянные проекты или пользовательские сессии.
Бэкенд проверяет владение видео, музыкой и сохранённым анализом; браузеру сервисный
токен не передаётся. Долгие вызовы выполняет существующий воркер через NATS.

При занятости вычислительного слота v1/v2 возвращается 429 с Retry-After.
Неизвестные/повторяющиеся поля и некорректный анализ дают 422; превышение размера
загрузки — 413. Отсутствующий MODEL_API_KEY — 503, ошибка облачной модели — 502.

## CLI из папки ai

Подготовка (платные облачные вызовы):

```bash
.venv/bin/python -m raw2reel_ai --env-file ../.env prepare \
  '../assets/video/Im_Coming_Back_For_Everything_The_Social_Network_get_save_com.mp4' \
  --output outputs/prepared.json
```

Файл содержит тот же JSON, что возвращает HTTP. Терминал выводит краткий список
персонажей и предупреждения без длинных base64-строк. Выберите ID по каталогу
и миниатюрам, затем:

```bash
.venv/bin/python -m raw2reel_ai --env-file ../.env render-v2 \
  '../assets/video/Im_Coming_Back_For_Everything_The_Social_Network_get_save_com.mp4' \
  --analysis outputs/prepared.json \
  --person p1 \
  --music '../assets/audio/ATSMXN, XTOM - Enemies [NCS Release].mp3' \
  --duration 20 \
  --output outputs/cloud-reel.mp4
```

Для нескольких персонажей повторить --person p2. Выбор означает «хотя бы один
из выбранных видим». --no-captions выключает видимые субтитры; текст реплик
всё равно используется при отборе. --overwrite разрешает замену выходного файла.

Рядом с MP4 CLI сохраняет .v2.json: сценарий, порядок сцен, исходные и выходные
таймкоды, impact_start, смещение музыки, координаты треков, просмотренные интервалы,
usage и предупреждения. HTTP возвращает только MP4.

Для диагностики добавить глобальный --debug перед prepare/render-v2:

```bash
.venv/bin/python -m raw2reel_ai --env-file ../.env --debug prepare ...
```

Он выводит исходный traceback. Ошибка face_catalog_limit отдельно сообщает,
что группировка превысила 64 карточки; это не проблема путей. Неуверенные
совпадения могут разделить одного человека на несколько карточек.

## Swagger

Запуск: `.venv/bin/uvicorn raw2reel_ai.main:app --env-file ../.env --port 8000`.
Открыть /docs, Authorize: AI_SERVICE_TOKEN без Bearer. В /v2/prepare выбрать видео;
скопировать/сохранить JSON-ответ. В /v2/render передать то же видео, весь ответ
в поле analysis, person_ids, музыку и настройки. Распаковка файлов не нужна.

## Как выполняется генерация

1. FFmpeg ищет склейки и делит длинные участки на части до 8 секунд.
2. SAM локализует лица на выбранных кадрах; при пустом результате используется
   Spark grounding. Spark группирует миниатюры по анонимным персонажам.
3. Voice транскрибирует звук исходника. Каталог и реплики входят в JSON подготовки.
4. После выбора персонажей SAM трекает лица в сценах с известными референсами.
5. Spark текстом ранжирует кандидатов по присутствию и транскрипции.
6. Spark смотрит только ограниченный обзорный монтаж, получает миниатюры выбранных
   персонажей и биты музыки, возвращает сценарий и структурированный EditPlan.
7. Валидатор проверяет исходные интервалы и длительность, пересчитывает выходную
   шкалу и impact_start после округления к кадрам.
8. FFmpeg выполняет кроп 9:16, монтаж, субтитры и сведение звука: речь приоритетна
   до impact_start, затем музыка усиливается, речь понижается; переход плавный.

## Бюджеты и ограничения

| Настройка | По умолчанию |
|---|---:|
| CLOUD_DISCOVERY_FRAMES | 48 кадров поиска |
| CLOUD_MAX_OBSERVATIONS | 128 наблюдений |
| CLOUD_TRACK_SECONDS | 120 секунд для SAM |
| CLOUD_REVIEW_SECONDS | 90 секунд видео для Spark |
| CLOUD_CLIP_SECONDS | 8 секунд на часть сцены |
| CLOUD_ANALYSIS_FPS | 5 FPS облачного анализа |

Это лимиты объёма, не денежная цена. Каталог строится по выборке; маленькие,
закрытые или короткие появления могут пропускаться. Группировка приблизительная,
склейки определяются эвристически. Unknown не считается доказанным отсутствием.
SAM может терять объект или сменить его после пропущенной склейки.

Кроп сглажен и сбрасывается между обнаруженными сценами. Если группа не помещается,
приоритет у первого выбранного персонажа. При потере трека используется центр.
Встроенные чёрные полосы не удаляются автоматически. Финальное видео — 720×1280,
30 FPS. Beat sync предлагается Spark, принудительного snap каждой склейки нет.
Spark может выбрать меньше запрошенной длительности при нехватке материала.

Повторный render-v2 использует готовую транскрипцию и каталог, но SAM-трекинг
и два прохода Spark выполняет заново. Постоянного кеша на AI-сервисе нет.
Работоспособность облачной связки проверялась на коротком реальном фрагменте;
это не гарантия полноты каталога или качества монтажа на всём фильме.
