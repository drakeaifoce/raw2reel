# Облачный пайплайн с выбором лиц (v2)

Все модели работают через Meta API и `MODEL_API_KEY`: SAM 3.1, Muse Spark,
Muse Voice Transcribe. Локально работают FFmpeg и Pillow; дополнительных
нейросетевых зависимостей/весов нет. Старые `render`, `analyze` и `/v1/render`
остаются совместимыми. v1 не начинает автоматически использовать v2.

## Как проверить из папки ai

В `../.env` нужны MODEL_API_KEY и локальные пути FFmpeg/ffprobe при необходимости.

```bash
.venv/bin/python -m raw2reel_ai --env-file ../.env prepare \
  '../assets/video/Im_Coming_Back_For_Everything_The_Social_Network_get_save_com.mp4' \
  --output outputs/prepared.zip
```

Это платный облачный анализ, ограниченный настройками ниже: ищет сцены,
локализует лица, сопоставляет анонимных персонажей и транскрибирует звук.
Команда выводит JSON с персонажами, observation IDs и статистикой вызовов.

Откройте ZIP: внутри `catalog.json` и реальные миниатюры `faces/oN.jpg`.
В `people` указан список персонажей с их `observation_ids`; каждая observation
содержит путь к миниатюре, bbox, таймкод и номер сцены. Посмотрите картинки
и выберите нужные ID. Например, если каталог вернул `p1`:

```bash
.venv/bin/python -m raw2reel_ai --env-file ../.env render-v2 \
  '../assets/video/Im_Coming_Back_For_Everything_The_Social_Network_get_save_com.mp4' \
  --artifact outputs/prepared.zip \
  --person p1 \
  --music '../assets/audio/ATSMXN, XTOM - Enemies [NCS Release].mp3' \
  --duration 20 \
  --output outputs/cloud-reel.mp4
```

Для нескольких персонажей повторите `--person p2`. Выбор означает «хотя бы один
из выбранных видим». `--no-captions` отключает видимые субтитры, но сохраняет
использование готовой транскрипции для отбора. Новая музыка/выбор не требуют
повторной подготовки. Для замены существующих выходов нужен `--overwrite`.
ZIP обязан соответствовать исходному видео по SHA-256.

Генерация: SAM трекает выбранные лица по сценам; Spark сначала отбирает
кандидатов по текстовым данным, затем смотрит ограниченный видеомонтаж и пишет
сценарий/план. FFmpeg выполняет план, кроп и субтитры. Музыка нормализуется:
до impact_start речь приоритетна, после — музыка усиливается, исходный звук
понижается, переход занимает примерно полсекунды. При отсутствии музыки
оригинальный звук сохраняется.

Рядом с MP4 появится `cloud-reel.v2.json`: сценарий, исходные и выходные
таймкоды, impact_start, смещение музыки, координаты треков, кандидаты,
просмотренные интервалы, usage облачных вызовов и предупреждения.

## HTTP и Swagger

Запуск из ai:

```bash
.venv/bin/uvicorn raw2reel_ai.main:app --env-file ../.env --port 8000
```

В `/docs` нажать Authorize и ввести AI_SERVICE_TOKEN без Bearer.

1. `POST /v2/prepare`: выбрать `video`, выполнить запрос, скачать `prepared.zip`.
2. Посмотреть `catalog.json` и JPEG в ZIP, выбрать person IDs.
3. `POST /v2/render`: выбрать то же `video`, ZIP в `artifact`, необязательную
   `music`; `person_ids` заполнить JSON-массивом, например `["p1"]`, задать
   `duration` и `captions`. Ответ — MP4.

В HTTP-ответе render возвращается MP4; подробный sidecar сохраняется только
при CLI-запуске. HTTP временные файлы очищаются после передачи результата.
Операции синхронные; v1/v2 делят один вычислительный слот. При занятости — 429.

## Подключение к приложению

Существующий backend worker всё ещё вызывает `/v1/render`. Для v2 нужны
дополнения со стороны backend/frontend; в этой доработке они не изменены:

1. После загрузки видео ставить prepare-задачу в существующую очередь NATS.
2. Воркер получает принадлежащее пользователю видео из MediaRepository,
   вызывает внутренний `http://ai:8000/v2/prepare` с сервисным токеном.
3. Сохраняет ZIP и миниатюры в Azure, каталог связывает с исходным media ID
   и владельцем. Разбирать архив с лимитами/allowlist, не использовать extractall.
4. Браузер получает каталог и защищённые media URLs миниатюр. Его выбор —
   person IDs из каталога, а не перезагруженные произвольные фото.
5. Задача рендера дополнительно хранит artifact media ID и selected person IDs.
   Воркер проверяет владение всеми файлами и отправляет видео, artifact, музыку
   и параметры на `/v2/render`; MP4 сохраняет привычным MediaRepository.create.

FastAPI не хранит аккаунты/постоянные проекты и не заменяет очередь бэкенда.
Не открывайте v2 как обход пользовательской авторизации: адреса предназначены
для серверных вызовов. MODEL_API_KEY и AI_SERVICE_TOKEN не отправлять браузеру.
Внешний доступ к v2 определяется существующим Caddy-конфигом; он здесь не менялся.

## Бюджеты и ограничения

| Переменная | По умолчанию | Что ограничивает |
|---|---:|---|
| CLOUD_DISCOVERY_FRAMES | 48 | Число кадров поиска лиц |
| CLOUD_MAX_OBSERVATIONS | 128 | Число сохранённых наблюдений лиц |
| CLOUD_TRACK_SECONDS | 120 | Секунды видео, отправляемые SAM для трекинга |
| CLOUD_REVIEW_SECONDS | 90 | Секунды видео, подробно просматриваемые Spark |
| CLOUD_CLIP_SECONDS | 8 | Максимальная длина клипа/части сцены |
| CLOUD_ANALYSIS_FPS | 5 | Частота кадров облачных видеоклипов |

Это лимиты объёма, не обещание конкретной цены. Локализация лиц и группировка
тоже оплачиваются: при пустом SAM-результате используется Spark grounding.
Подготовка никогда не посылает Spark весь исходный фильм для подробного просмотра.
Для каждого текстового запроса/картинок и видео отдельно сохраняется доступный
usage; вывод API не всегда содержит денежную стоимость.

Полнота каталога не гарантируется: маленькие, закрытые, короткие появления
могут пропускаться. Сопоставление между сценами приблизительное, неуверенные
совпадения могут дать несколько карточек одного человека. Можно выбрать обе.
Отсутствие наблюдения считается unknown, а не доказанным отсутствием.
Монтажные склейки определяются эвристически и могут быть пропущены; SAM может
терять объект/менять его после склейки. На первых длинных исходниках нужен
контроль каталога и результата, а не обещание безошибочного распознавания.

Кроп следует координатам со сглаживанием, сбрасывается на обнаруженных склейках.
Если несколько людей не помещаются, приоритет у первого выбранного. При потере
координат кроп возвращается к центру. Частота анализа 5 FPS ограничивает точность
трекинга примерно шагом .2 секунды; финальный ролик кодируется в 30 FPS.
Встроенные в исходник чёрные полосы автоматически не удаляются.
Spark может выбрать меньше запрошенной длительности, если материала не хватает.

## Проверка реализации

Новые тесты используют подмену облачных ответов, но настоящий FFmpeg для
подготовки, кропа, аудио и готового MP4. Платный smoke выполнялся отдельно на
четырёх секундах исходника: SAM face localization, группировка Spark, Voice,
SAM video tracking, два прохода Spark и финальный рендер. Это проверка
работоспособности API, не оценка качества/полноты на всём фильме.
