# Raw2Reel: изолированный Python-пайплайн

Работает с локальными файлами, без UI, Bun, базы данных и Azure Storage.
На входе MP4/MOV, на выходе настоящий вертикальный MP4 и JSON/SRT рядом с ним.

## Что делает

1. ffprobe проверяет формат, длительность, размер и потоки исходника.
2. Muse Voice Transcribe распознаёт речь и возвращает реплики с таймкодами.
3. Muse Spark анализирует нормализованное видео и транскрипт: предлагает хук,
   порядок фрагментов и описания видимых людей.
4. План проверяется: допустимые таймкоды, отсутствие пересечений и корректные ID.
5. При наличии музыки определяется её ритм, границы склеек сокращаются до долей.
6. FFmpeg собирает 9:16, переносит субтитры на новую шкалу, сводит звук и музыку.
7. ffprobe проверяет результат; временные файлы удаляются.

Рендер: 720×1280, 30 fps, H.264/AAC; максимум 30 секунд. Исходник: максимум
120 секунд, 150 MiB и 12 мегапикселей; музыка: максимум 10 минут и 32 MiB.
Если выбранные фрагменты короче заданной длительности, они не повторяются
и не растягиваются. При неопределённом ритме применяется обычная нарезка.
Длительности фрагментов округляются внутрь до целых кадров 30 fps; субтитры
и склейки используют ту же шкалу. Промежуточный звук хранится без сжатия,
чтобы задержка AAC не накапливалась на каждой склейке. Пропуски звука заполняются тишиной.
Субтитры используют ту же шкалу 720×1280: размер шрифта 36, нижний отступ 80
и боковые отступы 40. Это исключает увеличение шрифта из-за внутренней шкалы ASS.

## Установка

Нужны Python ≥3.12, uv и FFmpeg/ffprobe с libx264, AAC и фильтром subtitles/libass.
В `ai/Dockerfile` FFmpeg и шрифт уже добавлены. Локально FFmpeg устанавливается
отдельно, например `brew install ffmpeg` на macOS.

```bash
cd ai
uv sync --locked
cp .env.example .env

export FFMPEG_PATH="$PWD/.tools/ffmpeg"
export FFPROBE_PATH="$PWD/.tools/ffprobe"

```

Указать `MODEL_API_KEY` в `ai/.env` или окружении процесса. Ключ не выводится
в JSON-артефакты или ошибки. Для нестандартной установки доступны
`FFMPEG_PATH` и `FFPROBE_PATH` — абсолютные пути к бинарным файлам.
Без явных настроек пайплайн ищет инструменты сначала в `PATH`, затем в
`ai/.tools/ffmpeg` и `ai/.tools/ffprobe`. Каталог `.tools/` исключён из Git;
это постоянное локальное размещение, в отличие от очищаемого `/tmp`.

## Сразу создать ролик

```bash
uv run python -m raw2reel_ai render /path/to/source.mp4 \
  --output outputs/reel.mp4 \
  --duration 27 \
  --music /path/to/music.mp3
```

`--music` необязателен: без него сохраняется звук исходника. Для видео без
аудиопотока или с цифровой тишиной транскрипция пропускается. Флаг
`--no-captions` отключает субтитры и новый запрос транскрипции.

Этапы идут в stderr, итоговый JSON — в stdout. Ошибка завершает процесс с кодом 1.

Рядом с `reel.mp4` создаются:

- `reel.analysis.json` — план, транскрипт и SHA256 исходного видео;
- `reel.captions.srt` — субтитры по репликам на итоговой шкале;
- `reel.manifest.json` — реальные длительность, размер, склейки, BPM и предупреждения.

Существующие выходные файлы сохраняются; для их замены нужен `--overwrite`.
Выход и его дополнительные файлы не могут перезаписать ни один входной файл.

## Раздельно анализ и рендер

```bash
uv run python -m raw2reel_ai analyze /path/to/source.mp4 \
  --output outputs/source-analysis.json

uv run python -m raw2reel_ai render /path/to/source.mp4 \
  --analysis outputs/source-analysis.json \
  --subject p1 \
  --output outputs/reel.mp4
```

ID людей нужно брать из `analysis.subjects` сохранённого JSON. Несколько
`--subject` означают оставить фрагменты хотя бы с одним из выбранных людей.
Без этого флага используются все подходящие фрагменты. Если совпадений нет,
пайплайн возвращает ошибку.

Сохранённые анализ и транскрипт переиспользуются без новых вызовов Meta.
SHA256 проверяется, чтобы план другого видео не применился случайно.
`analyze --no-transcription` сохраняет только визуальный анализ; если затем
рендерить с субтитрами, потребуется отдельный запрос Voice. Можно передать
`render --transcript recording.json`: JSON-ответ Voice с `turns` или сам массив
реплик с полями `startMs`, `endMs`, `transcript`.

Для другого файла окружения глобальная опция ставится перед командой:

```bash
uv run python -m raw2reel_ai --env-file ../.env render source.mp4 -o outputs/reel.mp4
```

## Ограничения

- Выбор людей основан на приблизительных наблюдениях Spark по сценам.
  Биометрическое распознавание и точное сопровождение лица не реализованы.
- Кадр вписывается целиком в 9:16 с полями; автоматического движения кропа нет.
- Таймкоды Voice относятся к репликам, поэтому пословной подсветки нет.
- Локальных AI-моделей и GPU нет: анализ и распознавание выполняются у Meta.
- Качество поиска интересных моментов и ритма зависит от материала; JSON
  проверяется, но художественное качество нарезки требует просмотра.

## Python API

```python
from pathlib import Path
from raw2reel_ai.pipeline import ReelPipeline

with ReelPipeline() as pipeline:
    result = pipeline.render(
        Path("source.mp4"),
        Path("outputs/reel.mp4"),
        duration=20,
        on_progress=print,
    )
```

Основные модули: `meta.py` — HTTP-клиент, `models.py` — схемы ответа,
`planning.py` — интервалы и SRT, `media.py` — FFmpeg, `pipeline.py` — оркестрация,
`cli.py` — командная строка.

## Проверки

```bash
uv run pytest -q
uv run ruff check .
uv run ruff format --check .
```

Интеграционные тесты создают настоящее тестовое видео и выполняют настоящий
FFmpeg-рендер. Сетевой транспорт Meta подставной, ключ и платные вызовы для
тестов не нужны. Если FFmpeg/ffprobe отсутствуют, медиа-тесты пропускаются.
Для полного прогона нужно установить оба инструмента или задать их пути.

Существующее FastAPI-приложение со служебными `/health`, `/ready`, `/version`
сохраняется отдельно и для запуска пайплайна не требуется.
