# Raw2Reel AI

Единственный пайплайн: подготовка каталога лиц, выбор пользователя и генерация
эдита по выбранным персонажам. SAM 3.1, Muse Spark и Muse Voice работают через
облачный Meta API. Локально FFmpeg выполняет работу с медиа, Pillow — с миниатюрами.
AI не подключается к MongoDB/Azure и не хранит постоянные проекты.

## Установка

Нужны Python >=3.12, uv, FFmpeg и ffprobe. FFmpeg должен поддерживать libx264,
AAC и subtitles/libass. Dockerfile устанавливает FFmpeg и шрифты.

```bash
cd ai
uv sync --locked
```

Настройки перечислены в `.env.example`. Можно использовать `ai/.env` или общий
корневой `.env` через `--env-file ../.env`. Требуются MODEL_API_KEY для облачных
вызовов и AI_SERVICE_TOKEN для защиты HTTP API. CLI не требует сервисный токен.
Ключи не отправляются в браузер и не выводятся в результат.

Локально программы ищутся в PATH, затем в ai/.tools. При нескольких установках
задайте абсолютные FFMPEG_PATH / FFPROBE_PATH, например на ai/.tools/ffmpeg и
ai/.tools/ffprobe. В Docker используйте установленные Linux-программы из PATH,
пути к исполняемым файлам macOS в контейнер не передавайте.

## Два этапа CLI

Из папки ai:

```bash
.venv/bin/python -m raw2reel_ai --env-file ../.env prepare \
  ../assets/video/Im_Coming_Back_For_Everything_The_Social_Network_get_save_com.mp4 \
  --output outputs/prepared.json
```

Посмотрите catalog.people и thumbnails в JSON, выберите person ID:

```bash
.venv/bin/python -m raw2reel_ai --env-file ../.env render-v2 \
  ../assets/video/Im_Coming_Back_For_Everything_The_Social_Network_get_save_com.mp4 \
  --analysis outputs/prepared.json \
  --person p1 \
  --music '../assets/audio/ATSMXN, XTOM - Enemies [NCS Release].mp3' \
  --duration 20 \
  --output outputs/reel.mp4
```

Можно повторить --person для нескольких персонажей. --music необязателен,
--no-captions отключает видимые субтитры, --overwrite разрешает замену результатов.
Для стека с файлами, строками и именами функций используйте глобальный --debug перед командой.
Значения исключений не печатаются. Подробнее: [логирование](LOGGING.md).
Подготовка и генерация вызывают платные облачные модели.

Только prepare и render-v2 доступны в CLI; старых analyze/render больше нет.
Результат: MP4 720x1280, 30 FPS, H.264/AAC и подробный .v2.json рядом при CLI-запуске.
Исходник ограничен MAX_SOURCE_SECONDS (по умолчанию 1200), MAX_UPLOAD_BYTES
(150 MiB), музыка — MAX_MUSIC_BYTES (32 MiB). Монтаж фиксирован на 20 секундах; `duration` принимается для совместимости,
но текущий режим использует 20 секунд независимо от переданного значения.

## HTTP

```bash
.venv/bin/uvicorn raw2reel_ai.main:app --env-file ../.env --port 8000
```

Swagger: http://127.0.0.1:8000/docs. В Authorize ввести AI_SERVICE_TOKEN без Bearer.

- POST /v2/prepare: видео -> JSON с catalog, thumbnails, calls.
- POST /v2/render: видео, сохранённый JSON в analysis, выбранные person_ids,
  необязательная музыка и настройки -> MP4.
- GET /health: живость процесса.
- GET /ready: доступны ли исполняемые FFmpeg/ffprobe. Не делает запросы Meta
  и не проверяет действительность ключей; конфигурация облачного API проверяется
  при реальном запросе обработки.
- GET /version: версия развёрнутого сервиса.

Контракт, настройки фильтров и ограничения: [CLOUD_PIPELINE.md](CLOUD_PIPELINE.md).
Подключение к очереди и хранилищу бэкенда: [INTEGRATION.md](INTEGRATION.md).
Текущий backend worker требует отдельного перехода на двухэтапный HTTP-контракт.

## Модули

- cloud_pipeline.py — единственная оркестрация подготовки и генерации.
- cloud_meta.py / meta.py — запросы моделей, загрузка медиа, транскрипция.
- cloud_models.py / models.py — проверяемые схемы данных и интервалов.
- analysis.py — JSON-каталог и проверка JPEG-миниатюр.
- face_filters.py — настраиваемая фильтрация детекций до группировки.
- cloud_media.py / media.py — подготовка кадров и клипов, биты, FFmpeg-рендер.
- planning.py / reframing.py — шкала субтитров, округление к кадрам, динамический кроп.
- pipeline_io.py — SHA-256 исходника, JSON и проверка наличия PCM-сигнала.
- main.py / cloud_api.py / cli.py — HTTP и CLI.

## Двухчастный монтаж

Spark выбирает связное вступление (обычно 6–8 секунд, максимум два кадра) и
материал для быстрой второй части. Код собирает ровно 600 кадров при 30 FPS.
Если одобренного диалога мало, вступление будет короче; растягивания речи нет.
Во второй части короткие кадры обычно по 0,4–0,9 секунды, повторяются в другом
порядке при нехватке материала. Используются только проверенные интервалы.
Исходный звук выключается, субтитры исчезают, музыка играет с коэффициентом 0.5
после нормализации. Начало второй части совпадает с выбранным дропом саундтрека.
При отсутствии музыки вторая часть остаётся без исходного звука.

В первой части — короткие ASS-субтитры с жёлтой подсветкой текущего слова.
Синхронизация слов приблизительная: Voice даёт время реплик, отдельного
выравнивания слов нет. `--no-captions` отключает их. Во второй части — короткие
чередующиеся zoom in/out на стыках. На весь ролик накладывается мягкая коррекция
контраста/насыщенности и резкости. Дополнительных вызовов моделей для эффектов нет.

В `soundtrack.py` заданы точки дропа четырёх сэмплов по SHA-256 исходных файлов.
Они выбраны по измеренному подъёму басовой энергии, без ручной музыкальной разметки.
При перекодировании файла его отпечаток меняется. Для других файлов выполняется
ограниченный анализ первых 90 секунд; при отсутствии уверенного подъёма музыка
вступает с начала трека на границе частей. Если дроп раньше вступления, перед
началом саундтрека добавляется тишина, чтобы не сдвигать переход.

В `.v2.json` видны `impact_start`, `music_start`, `music_delay`, `music_drop`,
`music_drop_method`, `requested_duration`, `edit_style` и предупреждения о нехватке
материала. Перезапуск `prepare` не требуется: сохранённый анализ совместим.
