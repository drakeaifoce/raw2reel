# HTTP-интеграция генерации рилса

`main.py` вызывает тот же `ReelPipeline.render()`, что и CLI: распознавание речи,
анализ Meta, выбор сцен, монтаж FFmpeg, субтитры и сведение музыки.
Фронтенд и бэкенд этой доработкой не изменены; автоматического вызова с сайта пока нет.

## Настройка и запуск

В серверном `.env` задайте `MODEL_API_KEY` и отдельный случайный `AI_SERVICE_TOKEN`
(например, сгенерированный `openssl rand -hex 32`). Не отдавайте эти ключи браузеру.
В Docker зависимости FFmpeg уже устанавливает Dockerfile. Локально нужны ffmpeg
и ffprobe; при необходимости задайте абсолютные FFMPEG_PATH / FFPROBE_PATH.

Из `ai/`:

```bash
uv sync --locked
.venv/bin/uvicorn raw2reel_ai.main:app --env-file ../.env --host 127.0.0.1 --port 8000
```

## Контракт

`POST /v1/render`, `Authorization: Bearer <AI_SERVICE_TOKEN>`, multipart/form-data:

| Поле | Значение |
|---|---|
| video | Обязательный файл видео, до 150 MiB по умолчанию |
| music | Необязательный аудиофайл, до 32 MiB |
| duration | Длительность результата в секундах, больше 0 и до 30; по умолчанию 27 |
| captions | `true` (по умолчанию) или `false` |
| subject_ids | Необязательный JSON-массив ID персонажей; по умолчанию `[]` |

Ответ 200 — бинарный `video/mp4` с именем `reel.mp4`. Это синхронный запрос:
ответ приходит после полного монтажа. Временные исходники и результат удаляются
после передачи. Артефакты анализа и субтитров отдельно этим API не возвращаются.
Имена и пути файлов пользователя не используются как пути на сервере.

Ошибки: `{"error":{"code":"…","message":"…"}}`.
401 — неверный сервисный токен; 413 — превышен размер; 422 — неверные параметры
или ошибка обработки медиа; 429 — уже идёт генерация (повторить позже);
502 — ошибка Meta; 503 — не настроен сервисный ключ или MODEL_API_KEY.
Один процесс обрабатывает один рилс одновременно; запускайте один uvicorn worker.
Уже начатая генерация может продолжиться после отключения клиента.

Пример из `ai/` (переменная AI_SERVICE_TOKEN должна быть экспортирована):

```bash
curl --fail-with-body http://127.0.0.1:8000/v1/render \
  -H "Authorization: Bearer $AI_SERVICE_TOKEN" \
  -F 'video=@../assets/video/Im_Coming_Back_For_Everything_The_Social_Network_get_save_com.mp4' \
  -F 'music=@../assets/audio/ATSMXN, XTOM - Enemies [NCS Release].mp3' \
  -F duration=20 \
  -F captions=true \
  --output reel-http.mp4
```

## Что подключить в существующем бэкенде

1. Добавить защищённый пользовательской сессией маршрут генерации. Принимать ID
   уже загруженных видео/музыки и параметры, а не произвольные серверные пути/URL.
2. Проверить владение обоими файлами через существующий
   `media.get(id, principal.userId)`. Если файла нет — вернуть 404.
3. Отправить их содержимое через FormData на `http://ai:8000/v1/render` в Docker
   (локально `http://127.0.0.1:8000/v1/render`). В Authorization передать
   AI_SERVICE_TOKEN из серверного окружения. Content-Type для FormData выставит
   HTTP-клиент вместе с boundary; не задавать его вручную.
4. Проверить статус до чтения MP4; обработать JSON-ошибку и 429. Для запроса нужен
   длительный таймаут, например 15 минут, с учётом длины видео. Если браузерный
   запрос не должен ждать — запускать этот вызов из фоновой задачи бэкенда и
   возвращать ID задачи; очередь AI-сервис сейчас не реализует.
5. Сохранить успешный ответ через `media.create(new File([bytes], 'reel.mp4',
   {type: 'video/mp4'}), principal.userId)` и вернуть metadata / ID медиа.
   Существующий `GET /api/media/{id}` отдаст пользователю готовый файл.
6. Подключить действие генерации на фронтенде к новому маршруту бэкенда.

Caddy уже проксирует `/ml/*` на AI: внешний адрес этого маршрута будет
`/ml/v1/render`. Для вызовов бэкенда используйте внутренний адрес контейнера;
сервисный токен не является пользовательской авторизацией и не должен попадать
во фронтенд. Health/ready/version продолжают работать без сервисного токена.

Новый двухэтапный облачный поток с каталогом лиц и трекингом описан в
[CLOUD_PIPELINE.md](CLOUD_PIPELINE.md). Он доступен через /v2/prepare и /v2/render;
существующий worker продолжает использовать v1 до отдельного подключения v2.
